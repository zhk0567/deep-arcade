# 排行榜后台（v0.6.1 本地联调版）

本项目包含真正可运行的 Node.js HTTP 后台和持久化排行榜。它目前在本机运行；没有部署公网，也没有接入微信账号。所有连接到同一实例的浏览器使用同一榜单。

## 本地启动

双击 `开始游戏.cmd`，或在项目目录执行：

```powershell
node server.cjs --port 4173
```

也可指定独立数据位置和局域网监听地址：

```powershell
node server.cjs --host 0.0.0.0 --port 4173 --data-dir D:/合成大肥鱼/排行榜数据
```

默认仅监听127.0.0.1。手机访问需要手机和电脑可互通，并使用电脑在该网络中的地址；127.0.0.1只代表当前设备。不要把本地地址当作公网地址。

## 接口

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | /api/health | 版本和运行检查 |
| GET | /api/player | 建立或恢复浏览器玩家身份，HttpOnly Cookie保存凭证 |
| POST | /api/profile | `{name}`，1—12个字符的昵称 |
| POST | /api/runs | 发放随机种子和绑定玩家的签名对局凭证 |
| POST | /api/resume | 验证存档原凭证后按原种子续签 |
| POST | /api/score | `{run,moves,ticks}`，后台重放后计算分数，只更新最高分 |
| GET | /api/leaderboard | 前50名、上榜人数、自己的最高分和排名 |

POST使用同源JSON请求及 `X-FatFish-Request: 1`。不开放跨站提交。玩家Cookie凭证和签名密钥不会出现在榜单返回中。
`moves` 为 `[模拟帧编号, 投放横坐标]` 数组。暂停不消耗模拟帧，后台使用同版本物理逻辑核算。直接提交的score字段不参与计分。
单份记录最多4000次投放、108000个模拟帧（30分钟），核算在Worker线程中进行，最多2个并行任务，15秒超时。
接口错误会返回明确状态；前端对临时错误保留待保存记录，可重试。

## 持久化

默认 `runtime-data/leaderboard.ndjson` 是追加日志。每个玩家的有效状态只保留一个最高分；低分不追加成绩事件。日志保留状态变更，以便恢复和检查。
每次变更同步刷盘后再确认保存，重启加载日志恢复玩家和成绩。末尾不完整写入会截断到最后完整记录；中间完整记录损坏会停止加载，不会静默覆盖数据。
请备份整个数据目录，尤其是身份哈希和签名密钥。升级代码保留数据目录；不要将其复制到dist或公开目录。
这是单进程文件存储，不要让多个后台实例同时写同一目录。面向大量玩家或多实例部署时应迁移到共享数据库。

## 正式上线还需要什么

1. 准备可以长期运行Node.js的服务器，部署项目；用进程管理器保持单实例运行，并设置持久数据卷。
2. 通过HTTPS反向代理提供游戏和 `/api` 同源地址。设置 `FATFISH_SECURE_COOKIE=1`；只在HTTPS部署时启用。
3. 微信版接入玩家身份：由后台验证微信登录身份，将榜单主键绑定到微信用户，替换目前浏览器Cookie身份。昵称不是身份主键。
4. 将浏览器界面与音效适配到微信小游戏运行环境后，在开发者工具和真机验证网络、音效、刘海/胶囊区域与性能，再发布。

上述公网部署和微信身份适配尚未执行。代码不包含云账号或密钥，不需要为了本地联调提供账号。
