# 合成大肥鱼 · 微信小游戏骨架

这是从 `游戏原型/dist`（浏览器 H5 版）移植到微信小游戏的第一版骨架，目标只有一个：**先把「投放—合成—计分」跑通**，确认物理、手感和帧率在小游戏环境里站得住，再往上加界面。

## 一、怎么跑起来

1. 打开微信开发者工具，选择 **小游戏** 项目类型（不是小程序）。
2. 目录选到 `D:\合成大肥鱼\微信小游戏`。
3. AppID 填**你自己注册的小游戏 AppID**（`project.config.json` 里现在是占位符 `touristappid`，只能看不能上传）。还没有 AppID 就先去 mp.weixin.qq.com 注册个人主体小游戏。
4. 编译后应该直接进入对局：顶部是得分卡，下面是棋盘，按住屏幕左右拖动选位置，松手投放。

命令行自检（不需要开发者工具）：

```powershell
cd D:\合成大肥鱼\微信小游戏
node tools/headless-smoke.cjs
```

│  ├─ effects.js           碎粒、飘分、顶部提示

## 四、验证情况（诚实说明）

已做：**无头冒烟测试**，用最小的 wx 替身把 `game.js` 完整跑起来，实测结果——

```
投放 24 次，合成 18 次，得分 164
布局 390×594 @ scale 0.929，HUD 起点 y=90
最高分已存：164
```

覆盖了：自动开局、触摸投放、真实物理合成、计分、暂停时分数与球体冻结、切后台自动暂停、重开后归零、最高分落盘。

另外做了**布局自检**（`node tools/layout-check.cjs`），6 种常见尺寸全部通过：

| 机型 | 棋盘 | scale | 底部余量 |
|---|---|---|---|
| iPhone SE 320×568 | 264×402 | 0.628 | 16 |
| Android 360×640 | 308×470 | 0.734 | 16 |
| iPhone 8 375×667 | 321×489 | 0.764 | 16 |
| iPhone 13 390×844 | 390×594 | 0.929 | 55 |
| Pro Max 430×932 | 430×655 | 1.024 | 64 |
| 折叠屏 673×841 | 431×657 | 1.027 | 16 |

> 注意：320×568 这类小屏上棋盘只有 264×402，1 级球直径约 25px，偏挤但可玩。如果要照顾小屏，可以考虑把 `config.width` 从 420 降到 390 再重新标定半径。

**没做**：像素级外观验证。测试里的画布是空替身，只能证明代码路径不报错，**证明不了画面好不好看、字有没有重叠、球是否糊**。这一步必须在开发者工具和真机上看。

## 五、真机预览重点看这几件事

1. **棋盘是否完整可见**：390×844 上棋盘是 390×594，HUD 从 y=90 开始（胶囊下方）。换成 360×640 的小屏、或 430 宽的大屏各看一次。
2. **文字是否够大**：HUD 字号按 CSS px 写死（11/26px），在高 DPI 屏上应该清晰，但小屏可能偏挤。
3. **球面清晰度**：立绘只有 700px 宽，10 级（半径 136）实际绘制直径 272 CSS px，在 3 倍屏上会被放大到 816 物理像素。如果发糊，把 `tools/compress-assets.ps1` 的 `-Width` 提到 900 再压一次（包体还有 2.6MB 余量）。
4. **帧率**：满屏球堆时看开发者工具的帧率面板。若掉帧，先关掉 `scene.js` 里背景的三层波浪（每帧逐像素 sin 计算），或把物理步进从 2 个子步降到 1。
5. **触摸手感**：`clientX` 与棋盘坐标的换算在 `scene.toBoard`，如果感觉落点偏左/偏右，先查这里。

## 六、下一步建议顺序

1. **首页**（开始 / 继续）→ 2. **结算卡 + 图鉴**（复用 `tarot-data.js`，但先把「星海神谕」这类词改掉）→ 3. **语音与音效** → 4. **排行榜**（建议云开发，别自建）→ 5. **隐私授权 + 分享 + 适龄提示**。

界面层每加一块，`scene.js` 就加一个 `drawXxx()` 和一个按钮矩形，`game.js` 里加一个状态分支——保持「逻辑不碰画面，画面不碰逻辑」，后面 H5 版和小游戏版才能共用 `engine.js`。
